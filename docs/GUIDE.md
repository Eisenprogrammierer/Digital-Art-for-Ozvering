# ozart user guide

This is the practical guide to making assets with **ozart**, the procedural 2-D asset
generator in this repository. It covers the browser studio, the command line, every
asset family, the seed model, the build and licensing checks, and the things that
usually go wrong.

If you only read one section, read [Quick start](#quick-start) and
[The studio](#the-studio). The rest is reference.

## What this project makes

Every asset is computed from a seed and a small set of parameters:

```
asset = f(seed, params) -> PNG + JSON sidecar
```

Nothing is hand-drawn, traced, scraped or generated by an image model. The output is
yours to ship under the repository's MIT licence, and the sidecar records the function,
the seed and the parameters that made it, so any picture can be rebuilt or argued with.

The families are:

- **Characters** — figure sprite sheets, portraits, portrait sheets, lineage.
- **Heraldry** — coats of arms, flags, flag animations, faction sheets.
- **World** — strategic hex maps, campaign data, site close-ups, isometric boards.
- **Materials** — ground materials, tiling textures, the core material sheet.
- **Interface** — icons and atlases, nine-slice UI kits, the generated typeface.
- **Core** — palettes and the SDF reference sheet.

The outputs are deliberately ordinary files (PNG, JSON, SVG). There is no runtime, no
editor and no project format. A game loads the PNG and the table in the sidecar.

## Install

Requirements: Python **3.10+**, `numpy`, `Pillow`. The studio is standard library only
on top of that.

```bash
git clone <this repository>
cd Digital-Art-for-Ozvering
python -m pip install -r requirements.txt
```

Check the installation without drawing anything:

```bash
python cli.py --help
python cli.py figures --help
```

The local development environment used for the checked-in build is Python 3.14 with
numpy 2.5 and Pillow 12; CI also runs 3.10 and 3.13.

## Quick start

### Make one asset in the browser

```bash
python cli.py studio --port 8000
```

The command prints `http://127.0.0.1:8000/` and opens it. Choose an asset, set a seed,
press **Generate**. The picture appears with its files, sidecar, command and a zip.

### Make the whole demo

```bash
python cli.py demo --out out --seed 7
```

This takes roughly three to four minutes and writes the complete gallery, all sheets,
the credits screen and `out/index.html`. Open `out/index.html` in a browser.

### Make one sheet from the terminal

```bash
python cli.py figures --out out/figures.png --seed 7 --cycle walk --count 8
python cli.py iso     --out out/iso.png     --seed 7 --cols 11 --rows 8 --size 46
```

Each command writes the PNG and a `.json` sidecar beside it.

## The studio

`studio/` is a small local web page over the command line. It is the intended place to
experiment, because it shows the result, the files and the exact command in one view.

### Start and options

```bash
python cli.py studio                     # 127.0.0.1:8000, opens a browser
python cli.py studio --port 0            # ask the OS for a free port
python cli.py studio --root assets/work  # write somewhere else
python cli.py studio --no-browser        # do not open a window
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--host` | `127.0.0.1` | Interface to bind. Keep the default unless you mean to expose it. |
| `--port` | `8000` | `0` asks the OS for a free port; the printed URL has the real one. |
| `--root` | `out/studio` | Where renders are written. |
| `--no-browser` | off | Do not call `webbrowser.open`. |

The studio is a development workbench for one person on one machine. It has no
authentication and no upload. Do not bind `0.0.0.0` on a network you do not trust.

### The page

1. **What to make** — pick a generator. They are grouped by family.
2. **The form** — every field is a CLI flag. Numbers have ranges, choices are closed,
   and optional text is clearly marked.
3. **Generate** — runs the real command. The first render includes Python's startup
   (about two seconds); heavy assets take longer.
4. **The picture** — the primary output on a checkerboard so transparency is visible.
5. **This result** — every file the command wrote, with sizes and download links, a
   `bundle.zip`, the sidecar as JSON, and the command line that reproduces it.
6. **New seed** — a random seed for the current form. It does not generate by itself.

`Ctrl+Enter` / `Cmd+Enter` generates. The result's command is copyable and is the
bridge back to a script.

### Where the files go

Each render gets a token directory:

```
out/studio/20261020-201325-1a2b3c/
  iso.png
  iso.json
  bundle.zip          # made when you ask for it
```

The token is a timestamp plus six random hex digits, so two renders with the same
output name do not collide. The directory is a normal directory: copy it, commit the
PNG and JSON to a game project, or delete it. At startup the studio prunes directories
older than seven days and keeps at most the newest two hundred.

If you are extending the project, see [`studio/README.md`](../studio/README.md). The

## Seeds, sizes and reproducibility

A **seed** is the identity of an asset. The same seed and parameters produce the same
pixels and the same sidecar in the same environment. Change one number and you get a
different asset, not a variation of the same one.

- Seeds are ordinary non-negative integers. `0` is valid.
- A sheet of independent assets takes a base seed and adds the index; the sidecar
  records the per-cell seed or genome where that matters.
- Some generators have their own seed field in addition to the sheet's: a board's
  `--hero-seed` keeps one hero while the map changes.
- Sizes are output sizes, not resamples. A 512 px icon is *drawn* at 512 px from the
  same geometry. That is why the line width and bevel are pixel quantities.
- `--count` and `--cols` control how many cells a sheet has and how they wrap.
- Reproducibility is exact within the same Python/numpy/Pillow environment. Pin those
  versions if you need to rebuild a shipped asset byte for byte; a library's
  anti-aliasing or colour conversion can change across major versions.

Every exporter writes a JSON sidecar beside the picture:

- `source` — the module path that drew it, e.g. `procedural:gen.maps.iso`;
- `seed` and parameters;
- for maps, the province, river, road and realm data, and a separate campaign file;
- for sheets, the cell rectangles, the timeline and the per-cell specs;
- for the typeface, metrics and the characters drawn;
- for a board, the camera, terraces, material parameters and the hero's facing;
- for a figure sheet, the cycle, the facing, the frame table and the body's genome.

The sidecar is the asset's provenance. Keep it with the PNG. The credits gate reads it.

## Asset families

### Figures

A figure is one body at a sequence of phases, not a set of separate drawings. The
cycles are `idle`, `walk`, `run` and `attack`; `attack` is a one-shot inside a loop so
a game can play it once and fall back.

```bash
python cli.py figures --out out/figures.png --seed 7 --cycle walk --count 8
python cli.py figures --out out/figures.png --seed 7 --cycle walk --facing down
```

Use a figure sheet when you need a walk cycle, an idle, a run or an attack. Use
`--facing` to choose one of the four directions. The far limb is a depth cue in the
side view; in the front and back views both limbs are visible and the dark/light
separation is not used.

### Portraits

A portrait is a head as a stack of cross-sections, with a genome that can be traced,
mixed and bred. `portrait` draws one; `portraits` draws a sheet; `lineage` draws two
parents and their children. Style, hair, expression and the demographic genes can be
forced for a one-off without changing the others.

```bash
python cli.py portrait --out out/one.png --seed 5 --size 384
python cli.py portrait --out out/elder.png --seed 5 --age elder --climate arid
python cli.py portraits --out out/portraits.png --seed 7 --count 8 --size 256
python cli.py portraits --out out/women.png --seed 7 --sex female --count 8
python cli.py lineage --out out/lineage.png --seed 7 --children 6
```

`sex`, `age`, `climate` and `culture` are genes like any other. `sex` adjusts
presentation and a few proportions; `age` changes the life stage, greys the hair in
the colour script and adds age detail; `climate` is the environment a lineage adapted
to, so it shifts skin and feature ranges rather than drawing a costume; `culture`
chooses the dress tradition -- collar, trim and fastening -- and never the face.
`portraits` accepts the same four flags to pin one gene across the sheet. A DNA
string written before these genes existed still loads: missing demographic genes take
their documented defaults, while a missing shape or colour gene is still an error.

### Heraldry

A coat is a specification: shield, field, division, charges and tinctures. A faction
is a name hashed into a coat, a banner and a livery; the name is the input, not the
seed. A flag is a cloth field: bands by projection, folds as normal displacement, a
pole and a fly. An animation is the same flag sampled along its own `t`.

```bash
python cli.py arms --out out/arms.png --seed 7 --count 12
python cli.py flags --out out/flags.png --seed 7 --count 12 --ratio 3:2 --hang bar
python cli.py anim --out out/anim.png --seed 7 --count 12 --fps 12
python cli.py factions --out out/factions.png --name "Kingdom of Alder" \
                        --name "The Salt League"
python cli.py blazon --out out/one.png --seed 5
```

`blazon` prints a textual blazon and draws the coat, so the description and the
picture can be compared.

### Maps

`maps` draws the strategic view: terrain, relief, coast, rivers, roads, provinces,
realms, names and a campaign JSON. It is the wide view where a hex is a piece of
information.

```bash
python cli.py maps --out out/maps.png --seed 7 --count 1 --cols 26 --rows 17 \
                    --sea 0.42 --provinces 8 --factions 4
python cli.py maps --out out/maps.png --seed 7 --no-names
```

For each map the demo also writes `out/maps.campaign.<seed>.json`: the map as data, not
pixels. That file is what a game without this generator loads.

### Sites and boards

`site` is the camera down: the same kind of terrain, but the ground is the subject. It
draws two panels by default — the biome colour on the left and the material on the
right — with a carved river, cliffs and a wet shore. `--flat` draws only the colour
panel.

```bash
python cli.py site --out out/site.png --seed 7 --size 56 --cols 8 --rows 6
python cli.py site --out out/site.png --seed 7 --size 56 --river-fraction 0.90
```

`iso` is a board from the south: terraced hex prisms, world-sampled tops, dirt cliffs,
foam, and a figure. Only south-facing faces are drawn, rows are painted far to near,
and the hero is inserted after its row.

```bash
python cli.py iso --out out/iso.png --seed 7 --cols 11 --rows 8 --size 46
python cli.py iso --out out/iso.png --seed 7 --cols 11 --rows 8 --size 46 \
                   --hero 3,5 --facing down
```

`--hero` is `row,col`. It must be inside the grid and on land; a bad hex stops with a
message and no file. `--hero-seed` keeps the figure independent of the map seed.
`--levels` is the number of terraces, `--rise` the height exaggeration, and `--sea`
the sea fraction.

**A known limitation, stated plainly:** `maps`, `site` and `iso` generate their own
geography at the grid size you ask for. `terrain.fields` normalizes by the grid extent,
so a site or board at `--cols 8 --rows 6` is not a crop of the 26×17 strategic map at
the same seed — it is a different island of the same kind. A window/crop mode is not
implemented. If you need a specific place in a game, generate the strategic map and its
campaign file, and treat the site/board as a separate illustration; or use the same
seed and shape for a family of pictures and accept that they are siblings, not crops.

### Coast and border tiles

`coast` is the map's edge made into an asset: all sixty-four combinations of a hex's
six sides, the biome-border panel, and a count of how many of the tiles the demo maps
actually wear. A game blits a tile where the edge key says instead of walking a
polyline. The sheet itself is seed-independent; the seed only chooses the maps that
are counted.

```bash
python cli.py coast --out out/coast-tiles.png --size 20 --count 2
```

The command also writes `borders.png`, the same map with and without the inland biome
border, so the difference the border layer makes is visible.

### Materials

`grounds` draws six ground materials from one painter and a table of fifteen fields per
row. `tiles` draws Truchet, Wang, Gray-Scott and boards, with measured seam error.
`texture` is the core fBm/marble/wood/stone sheet.

```bash
python cli.py grounds --out out/grounds.png --seed 7 --size 256
python cli.py tiles --out out/tiles.png --seed 7 --size 256
python cli.py tiles --out out/tiles.png --seed 7 --size 256 --mips 4
python cli.py texture --out out/texture.png --seed 3 --size 256
```

`--mips N` writes a sheet per mip level and packs each level separately. `--no-atlas`
skips the packed atlas when you only want the sheet.

### Icons and UI

Icons are a plate with a charge, a badge for a count or tier, and a faction livery on
the plate. The command writes the set, a size sweep, the packed atlas and a sidecar
with every rectangle.

```bash
python cli.py icons --out out/icons.png --seed 3 --count 8 --size 192 \
                    --sizes 32,64,128 --cols 9
python cli.py icons --out out/icons.png --seed 3 --count 8 --name "Kingdom of Alder"
```

UI kits are nine-slice frames: the asset is `(PNG, corner insets, minimum size)`, not
just the picture. `--svg` also writes each kit as vector curves.

```bash
python cli.py ui --out out/ui.png --seed 7 --count 3 --scale 2
python cli.py ui --out out/ui.png --seed 7 --count 3 --scale 2 --svg
```

### Text

The typeface is generated from skeletons and a pen: 214 characters, five faces, metrics,
kerning and five ligatures. It is not a system font and needs no font file.

```bash
python cli.py text --out out/text.png --size 20
python cli.py text --out out/text.png --size 20 --face text
```

Use `--help` for the current face names.

### Core

`palette` draws a seeded set of OKLCH swatches resolved to sRGB. `shapes` is the SDF
reference sheet: the primitives every other generator draws with.

```bash
python cli.py palette --out out/palette.png --seed 3 --count 6
python cli.py shapes --out out/shapes.png
```

## The four hero facings

`figures` and `iso` accept `--facing`:

| Value | What it means | How it is drawn |
| --- | --- | --- |
| `right` | across the screen, `+x` | the profile rig, unchanged |
| `left` | across the screen, `-x` | the finished right sprite, mirrored exactly |
| `down` | towards the camera (south) | a front view: same skeleton, limbs given a side, wide chest, head with no nose and a hair cap |
| `up` | away from the camera (north) | a back view: same body, the head covered in hair, no face |

`up` and `down` are not a rotation of the side view and not a second body plan. They are
the same joints arranged head-on, which is why a four-direction hero has one set of
proportions, one palette and one gait. The sidecar records the facing, so a sheet or a
board can be rebuilt with the same direction.

The board's default is `right`, so unchanged commands produce unchanged bytes. The
figure's mirror is exact: `left` is `right` flipped after drawing, alpha and colour
together.

## Maps, sites and boards

The three world views are deliberately different cameras:

- **`maps`** — the strategic view, one raster pass, fourteen-ish pixels per hex. It is
  about information: biome, owner, roads, names.
- **`site`** — the close-up, where the hex is large enough to ask what it is made of.
  The ground is sampled in world coordinates, lit once with the terrain height, and the
  sea is masked exactly. Rivers are carved into the height field; cliffs and a wet shore
  are overlays on the land.
- **`iso`** — the board a player looks at. Orthographic axonometry from the south,
  terraced hex prisms, only the south faces, rows far to near, and a figure inserted in
  its row. The camera is fixed on purpose; the figure has four billboard facings rather
  than a free yaw.

The projection is:

```
screen_x = x
screen_y = -y * squash - height * rise
```

`--rise` exaggerates height because a real island's relief would be a few pixels at
this scale. `--levels` controls how many terraces the land is quantised into; more
levels means more, smaller steps.

## The full build

```bash
python cli.py demo --out out --seed 7
```

The demo writes every sheet and sidecar, the coast/border tiles, the grounds and
atlases, the site and board, the type specimen, the factions, the credits screen and
`out/index.html`. It takes roughly three to four minutes and is deliberately a single
process; do not run two demos at once.

A release is checked, not assumed:

```bash
python -m pyflakes cli.py core gen export studio tests
python tests/test_core.py
python tests/test_heraldry.py
python tests/test_portraits.py
python tests/test_ui.py
python tests/test_maps.py
python tests/test_textures.py
python tests/test_cli.py
python tests/test_icons.py
python tests/test_text.py
python tests/test_figures.py
python tests/test_gallery.py
python tests/test_studio.py
python cli.py credits --manifest out --check
python cli.py gallery --manifest out --stats
```

The suites do not need `pytest`; each file runs as a script and prints `n/n passed`.
`pytest` also works. To prove determinism, build the demo twice into different
directories and compare every file:

```bash
python cli.py demo --out /tmp/build-a --seed 7
python cli.py demo --out /tmp/build-b --seed 7
diff -r /tmp/build-a /tmp/build-b
```

The build is deterministic if the two trees are byte-identical.

## Credits and licensing

The code is MIT. The generated PNGs have no third-party rights attached; keep the seed
and sidecar so they can be rebuilt.

The one external asset is music by **Kevin MacLeod**, licensed **CC BY**. Attribution
is mandatory when you ship it. The repository keeps the attribution in
`core/credits.py` and copies it into every build:

```bash
python cli.py credits --manifest out          # print what is owed
python cli.py credits --manifest out --out out  # write out/credits.txt
python cli.py credits --manifest out --png out/credits.png
python cli.py credits --manifest out --check  # exit 0 only if the build is shippable
```

`--check` reports, it does not repair. It fails when:

- a curated source is missing a required field (a code problem);
- a picture has no sidecar or a sidecar names an unknown source (a build problem);
- an attribution required by the build is not present in the credits on disk (the
  forgetting problem).

The gallery also shows the gate's verdict in the gate's own words. Do not fake a
sidecar to silence the gate; add the missing source or regenerate the asset.

## Troubleshooting

**`ModuleNotFoundError: No module named 'numpy'` / `PIL`**
Install the requirements with the same interpreter you use to run `cli.py`:
`python -m pip install -r requirements.txt`.

**The studio port is in use**
Use `--port 0` (the printed URL has the real port) or another number:
`python cli.py studio --port 8010`.

**The browser did not open**
The server is still running; open the URL it printed. Next time add `--no-browser`
and open it yourself.

**A render is slow**
The first request includes Python startup. `maps`, `site`, `iso`, `grounds`, `tiles`,
`icons` and `text` can take seconds to a minute. The studio serializes renders, so a
second request waits rather than competing. The status line says what is happening.

**`iso: the hero's hex ... is water`**
The named hex must be land. Omit `--hero` to let the board choose the nearest plain to
the middle, or choose a land hex. An off-grid hex is refused the same way, with a
message rather than a traceback.

**`iso: the hero's hex ... is off a ROWSxCOLS map`**
The hex is outside the grid; rows and columns are zero-based and ordered `row,col`.

**The gallery links are broken**
Regenerate it from the build directory: `python cli.py gallery --manifest out`. If you
moved the HTML without the pictures, build the embedded version:
`python cli.py gallery --manifest out --embed`.

**`credits --check` fails after I added a picture**
The picture needs a sidecar and a known source. Regenerate it with the CLI rather than
copying a PNG into `out/`; the exporter writes the sidecar. If it is a curated external
asset, add it to `core/credits.py` with the required fields.

**The site/board does not look like my strategic map**
They are separate geographies at the grid size you ask for, not crops. See
[Maps, sites and boards](#maps-sites-and-boards). Use the campaign JSON for the
strategic map's actual data.

**The output is not byte-identical on another machine**
Pin Python, numpy and Pillow. Floating-point and anti-aliasing details can change
between library versions even when the algorithm is unchanged.

**The studio's old download link is gone**
Startup cleanup removes render directories older than seven days or beyond the newest
two hundred. Generate again; every render is reproducible from its command and seed.
